# 📒 Depter

### Тетрадь долгов, которая считает сама

Веб-приложение для малого бизнеса: магазины, ларьки и точки, где товар отпускают «в долг».<br>
Забудьте про тетради, калькуляторы и споры «я же отдавал».

**Меньше бумаги · Меньше ошибок · Больше времени на бизнес**

`Python` · `Django` · `PostgreSQL` · `RU / KY` · `светлая и тёмная тема`

</div>

## 💡 Зачем это нужно

В тысячах магазинов долги покупателей до сих пор записывают в тетрадь: «Нурсултан, 500 сом». Тетрадь теряется, страницы рвутся, цифры не сходятся, а бухгалтер в конце месяца часами сверяет записи вручную.

**Depter переносит эту тетрадь в браузер** и берёт на себя всю рутину:

| Было | Стало |
|---|---|
| Записи от руки, почерк, помарки | Запись долга за 10 секунд, с телефона или с компьютера |
| Сумму долга считают в уме или на калькуляторе | Баланс каждого клиента считается автоматически |
| «Сколько нам должны в сумме?» | Ответ на главной странице, без пересчёта |
| Бухгалтер сверяет тетради по филиалам | Все филиалы в одном месте, выгрузка в Excel одной кнопкой |
| Непонятно, кто и когда что записал | У каждой операции есть автор, время и журнал действий |
| Ошибку можно только зачеркнуть | Любую операцию можно отменить, при этом история остаётся честной |

## ✨ Возможности

### 🛒 Для продавца: быстро и просто
- **Записать долг** в пару нажатий: «Нурсултан купил на 500 сом». Имена клиентов подсказываются, телефон сохраняется.
- **Погасить долг** полностью или частично: система сама вычтет сумму и покажет остаток.
- **Список должников** с суммой напротив каждого имени и кнопками «Добавить долг» и «Погасить долг» прямо в строке.
- **История по дням**: когда клиент брал в долг, когда возвращал и сколько.
- **Старые долги из тетради** можно внести задним числом: дата долга и дата записи хранятся отдельно.
- Удобно на телефоне: внизу экрана панель с большой кнопкой «+ Долг».

### 👑 Для владельца: полный контроль
- **Несколько филиалов** и сотрудники, привязанные к своим точкам.
- **Наглядная главная страница**: общий долг, сколько выдано, сколько вернули, топ должников.
- **Понятный график** за 7, 14 или 30 дней. Красные столбики показывают, сколько взяли в долг, зелёные показывают, сколько вернули. Рядом кольцо «сколько уже вернули»: из каждых 100 сом, выданных в долг, вернули столько-то.
- **Отмена ошибочных операций** без удаления: создаётся обратная запись, и оба действия остаются в истории.
- **Запрет долга** недобросовестным клиентам и **архив** тех, с кем всё закрыто.
- **Журнал действий**: кто, что и когда делал. Записи нельзя изменить или удалить.
- **Выгрузка в Excel (CSV)** за любой период, готовая для бухгалтера.

### 🎨 Приятно пользоваться
- Две темы, **светлая и тёмная**, выбор запоминается.
- Два языка, **русский и кыргызский**, переключатель в шапке.
- Анимации, цветные иконки, адаптивный дизайн для телефона, планшета и компьютера.

## 🛡️ Надёжность: деньги не терпят «почти правильно»

Приложение работает с финансовыми данными, поэтому в нём заложены строгие правила:

- **Записи неизменяемы.** Операции нельзя править или удалять ни через сайт, ни через админку. Ошибки исправляются отменой.
- **Без дублей.** Двойное нажатие «Погасить» создаёт одну запись, а не две.
- **Без гонок.** Одновременные платежи от нескольких продавцов не приведут к переплате или отрицательному балансу: проверено тестами на PostgreSQL.
- **Данные организаций изолированы.** Один магазин не видит данные другого, а продавец видит только свой филиал.
- **Защита входа.** После 5 неверных паролей вход временно блокируется, cookies защищены, секреты хранятся в `.env`.
- **Резервные копии с проверкой.** Команда бэкапа сама проверяет, что копию можно восстановить.
- **74 автотеста** на финансовую логику, роли, доступ и безопасность.

## 🚀 Быстрый старт

```bash
cd Depter && source venv/bin/activate
python manage.py migrate
python manage.py runserver
```

Откройте http://127.0.0.1:8000/register/ и создайте аккаунт владельца: название магазина, имя, логин и пароль (от 10 символов). Филиал «Основной филиал» создастся автоматически. Продавцов добавляйте в разделе **«Работники»**.

Админка Django находится по адресу `/control-panel/` (его можно поменять в `.env`) и доступна только суперпользователю:

```bash
python manage.py createsuperuser
```

Тесты:

```bash
python manage.py test apps
```

## ⚙️ Настройка и запуск на сервере

Все настройки хранятся в файле `.env` (пример: `.env.example`). Файл `.env` **нельзя** коммитить в git.

```ini
DJANGO_SECRET_KEY=...            # python -c "from django.core.management.utils import get_random_secret_key as g; print(g())"
DJANGO_DEBUG=0
DJANGO_ALLOWED_HOSTS=depter.example.com
DJANGO_CSRF_TRUSTED_ORIGINS=https://depter.example.com
DJANGO_ADMIN_URL=control-panel
DJANGO_BEHIND_PROXY=1            # если приложение стоит за Nginx
DJANGO_SECURE=1

DB_NAME=depter
DB_USER=depter
DB_PASSWORD=...
DB_HOST=localhost
DB_PORT=5432
```

### Nginx и HTTPS

HTTPS на сервере обязателен.

```nginx
server {
    listen 443 ssl http2;
    server_name depter.example.com;
    # ssl_certificate ... (certbot)
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
server { listen 80; server_name depter.example.com; return 301 https://$host$request_uri; }
```

Gunicorn должен слушать только `127.0.0.1`, чтобы заголовок `X-Forwarded-For` нельзя было подделать снаружи. С `DJANGO_BEHIND_PROXY=1` блокировка входа видит настоящий IP посетителя, а не адрес Nginx.

Проверка перед запуском:

```bash
DJANGO_DEBUG=0 python manage.py check --deploy
python manage.py test apps
```

### Резервные копии

Раз в сутки через cron (`crontab -e`):

```cron
15 3 * * * cd /путь/к/Depter && ./venv/bin/python manage.py backup_db --keep 14 >> backups/backup.log 2>&1
```

Команда сама проверяет копию. Копии нужно регулярно вывозить на другую машину (rsync, rclone, S3): копия рядом с базой не спасёт при потере сервера.

Раз в месяц делайте полную проверку восстановления (создаёт и удаляет временную базу, нужны права `createdb`):

```bash
python manage.py verify_backup backups/depter-XXXX.dump --restore-test
```

Копия, которую ни разу не восстанавливали, это ещё не копия.

Восстановление: `createdb depter_new && pg_restore --no-owner -d depter_new backups/depter-XXXX.dump`
